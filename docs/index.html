The Invisible Payment

Money nobody can see until the receiver reveals it. Built on Tari Ootle for the Tari November Build Contest.

SIMULATION. This section runs the payment logic in your browser. No real TARI moves here. The on-chain template is the Rust code in this repo (src/lib.rs); its engine tests pass against the real Tari engine. A live mode is below, under “On-chain (live)”: connect a Sapient wallet on Esmeralda and it talks to the published template. Until the template address is pasted into config.js, the live mode can connect and read the epoch but cannot lock funds.

The idea. A sender locks TARI in a vault. On Ootle, native TARI is a stealth resource: the amount and the owner are hidden from observers. The payment opens only after a reveal epoch, only to the named receiver, and only with the secret phrase. Until then there is nothing to see. Then the receiver types the secret — and the money appears.

What this proves

The Rust template (src/lib.rs) enforces the same checks this page simulates, and its tests (tests/test.rs) run against the real Tari engine: reveal blocked before the epoch, reveal blocked with a wrong secret, reveal blocked for a non-receiver, reveal succeeds after the epoch with the right secret, cancel works before the epoch and is blocked after it. Run them with cargo test.

Honest limits: this demo is a simulation, not a live deployment. The template is not published to Esmeralda yet — that needs a funded Sapient wallet. The live mode above is wired and ready; it activates once the template address is pasted into config.js (see the README for the publish steps). The invisibility is the stealth property of native TARI on Ootle: amounts and owners are hidden from observers on chain. The epoch length on the live network is a fixed number of base-layer blocks; this demo does not state that number because the docs do not give it.
